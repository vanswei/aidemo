# AI 分析后端接入设计

## 目标

在当前小红书与视频号运营驾驶舱项目中新增一个同仓后端服务，用于对当前看板数据执行手动触发的 AI 分析。前端只展示分析结果，不处理任何模型密钥或网关配置。

本次设计同时包含一个小的前端调整：移除总览区域中“总粉丝量”相关展示。

## 范围

本次只做以下内容：

- 将当前单一前端项目整理为同仓双目录结构：`frontend/` 与 `backend/`
- 新增一个基于 Node.js + Express + TypeScript 的后端服务
- 后端支持 OpenAI 兼容接口，通过环境变量读取 `baseURL`、`apiKey`、`model`
- 前端新增一个“AI 分析”展示区，支持手动触发分析
- 前端向后端发送当前筛选后的聚合摘要，不直接发送密钥
- 前端支持分析中的加载态、错误态、结果态
- 移除总览区域中“总粉丝量”文案

本次不做以下内容：

- 不做自动分析触发
- 不做分析历史记录
- 不做多用户配置管理
- 不做数据库持久化
- 不做流式输出
- 不做前端自填 URL 或 Key

## 仓库结构

目标结构如下：

```text
frontend/
  src/
  package.json
backend/
  src/
  package.json
package.json
README.md
```

说明：

- `frontend/` 保留现有 Vite + React + TypeScript 驾驶舱
- `backend/` 新增 AI 分析服务
- 根目录 `package.json` 负责统一启动命令，例如同时启动前后端

## 后端技术方案

推荐方案：

- Node.js
- Express
- TypeScript
- OpenAI 官方 SDK，以 `baseURL` 方式兼容 OpenAI 兼容网关

选择原因：

- 与现有前端同技术栈，维护成本最低
- Express 足够覆盖当前体量
- OpenAI SDK 对兼容网关支持简单直接

## 环境变量

后端通过 `.env` 读取以下配置：

- `OPENAI_BASE_URL`
- `OPENAI_API_KEY`
- `OPENAI_MODEL`
- `PORT`

要求：

- 前端不得读取这些变量
- `.env.example` 需要提供示例
- 当配置缺失时，后端接口返回明确错误

## API 设计

### `GET /api/health`

用途：

- 健康检查
- 前端可用于判断后端服务是否已启动

响应示例：

```json
{
  "ok": true
}
```

## 后端内部职责

后端内部拆成以下模块：

- 配置模块：读取并校验环境变量
- 路由模块：定义 `/api/health` 与 `/api/analyze`
- 分析服务模块：构造 prompt、调用模型、解析响应
- 校验模块：校验前端传入摘要结构

边界原则：

- 路由层不直接拼 prompt
- 模型调用逻辑不与 Express 耦合
- 响应必须是结构化 JSON，不把整段自由文本直接返回给前端

## Prompt 策略

后端提示词需要强制模型返回固定 JSON 结构，避免前端解析不稳定。

分析重点限定为：

- 总体表现判断
- 平台差异
- 风险提醒
- 下一步建议

约束：

- 只基于传入数据分析
- 不允许编造不存在的数据
- 输出中文
- 每个字段简洁可读，适合前端直接展示

## 前端改动

### 1. 总览区调整

- 删除“总粉丝量”相关说明文案
- 保留曝光、涨粉、互动等更直接的运营指标

### 2. AI 分析卡片区

在驾驶舱中新增一块独立分析卡片，建议放在上半区或中部分析区附近。

需要包含：

- 标题，例如“AI 运营分析”
- 一句说明文案
- “开始分析”按钮
- 分析中的加载状态
- 调用失败时的错误提示
- 成功后的四段内容展示：
  - 总体判断
  - 平台洞察
  - 风险提醒
  - 建议动作

### 3. 发送数据策略

前端点击按钮时，不发送原始导入文件内容，而是发送当前筛选结果下的聚合摘要。

原因：

- 请求体更小
- 语义更稳定
- 更符合“驾驶舱分析”而不是“原始数据清洗”

## 错误处理

后端需要处理以下错误：

- 环境变量缺失
- 模型调用失败
- 上游接口超时
- 模型返回非 JSON
- 请求体结构非法

前端需要处理以下错误：

- 后端不可达
- 分析接口返回失败
- 分析结果字段缺失

用户可见原则：

- 错误提示必须是中文
- 失败后可以重复点击重新分析

## 测试策略

后端测试：

- 配置校验测试
- `/api/health` 接口测试
- `/api/analyze` 请求体校验测试
- 分析服务的模型响应解析测试

前端测试：

- “开始分析”按钮触发请求
- 加载态展示
- 成功态展示四类结果
- 失败态展示错误提示
- 总览区不再显示总粉丝量文案

## 实施顺序

1. 调整项目目录结构为 `frontend/` 与 `backend/`
2. 搭建后端基础服务与环境变量加载
3. 实现分析接口协议与响应结构
4. 在前端增加 AI 分析展示区
5. 接入前后端调用
6. 移除总览中的总粉丝量展示
7. 完成测试与文档更新

## 风险与控制

风险：

- 项目目录重组会影响现有前端脚本与路径
- 模型返回不稳定可能导致前端展示失败
- 分析请求若直接发送原始数据会膨胀

控制措施：

- 目录重组后优先修复并验证前端启动命令
- 强制后端做 JSON 结构化输出与解析兜底
- 仅发送聚合摘要，不发送原始文件
